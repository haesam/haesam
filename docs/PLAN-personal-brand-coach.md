# 퍼스널브랜드 코치 — 미끼자료(리드마그넷) 원페이지 기획안

> 목적: 미끼자료(무료 전자책/체크리스트 등) 신청을 받고 이메일 DB를 수집하는 단일 목적의 랜딩페이지.
> 원칙: **한 페이지 = 한 가지 행동(이메일 제출)**. 외부 이탈 링크 최소화, 네비게이션 없음.

---

## 1. 전략 개요

| 항목 | 내용 |
|---|---|
| 페이지 목적 | 미끼자료 신청 → 이메일 수집 → 뉴스레터/상담 퍼널로 연결 |
| 타겟 | 퍼스널브랜딩을 시작하고 싶은 1인 기업가, 프리랜서, 직장인 (SNS 계정은 있지만 방향을 못 잡은 사람) |
| 핵심 전환 행동 | 이메일 입력 후 "무료로 받기" 버튼 클릭 (단일 CTA) |
| 목표 전환율 | 콜드 트래픽 기준 15~25% (리드마그넷 랜딩 평균) |
| 유입 경로 | 인스타그램 프로필 링크, 스레드/블로그 포스팅, 광고 |

### 미끼자료 컨셉 (예시 — 실제 자료에 맞게 교체)
- **가제**: 『팔로워 0명에서 시작하는 퍼스널브랜딩 7일 로드맵』 (PDF)
- 형태: 체크리스트/워크북형 PDF — "즉시 실행 가능"이 핵심 소구점
- 전달 방식: 제출 완료 화면에서 다운로드 링크 제공 + (선택) 이메일 자동 발송

## 2. 페이지 구조 (섹션 순서 & 카피 방향)

모바일 우선. 스크롤 총 길이 5~6 스크린 이내로 짧게.

### ① Hero (첫 화면에서 폼까지 보이게)
- **아이캐치 라벨**: `무료 PDF · 5분 안에 받아보세요`
- **헤드라인 (H1)**: 결과 중심 카피
  - 예: "팔로워 수보다 중요한 건 **당신이 어떤 사람으로 기억되는가**입니다"
  - 대안: "퇴근 후 1시간, 7일이면 퍼스널브랜드의 뼈대가 잡힙니다"
- **서브카피**: 미끼자료가 무엇이고, 받으면 뭘 할 수 있는지 1~2문장
- **이메일 폼 (1차)**: 이름(선택) + 이메일 + CTA 버튼 "무료 로드맵 받기"
- **신뢰 마이크로카피**: "스팸 없음 · 언제든 구독 해지 가능"
- 비주얼: 미끼자료 목업 이미지(PDF 표지 3D 목업) 또는 코치 프로필 사진

### ② 문제 공감 (Pain)
- 헤드라인: "혹시 이런 상태 아닌가요?"
- 불릿 3~4개 (체크 아이콘):
  - 계정은 만들었는데 뭘 올려야 할지 모르겠다
  - 남들 따라 콘텐츠를 올려봐도 반응이 없다
  - '나만의 컨셉'이라는 말이 제일 어렵다
  - 시작한 지 오래됐는데 여전히 제자리다

### ③ 미끼자료 소개 (What's Inside)
- 헤드라인: "로드맵 안에 담긴 것들"
- 목차 미리보기 형태의 카드/리스트 5~7개 (Day 1 ~ Day 7 구성이면 그대로 노출)
  - 예: Day 1 나를 한 문장으로 정의하기 / Day 2 타겟 페르소나 좁히기 / … / Day 7 첫 콘텐츠 발행
- 각 항목에 "이걸 하면 얻는 것" 한 줄씩

### ④ 코치 소개 (Authority)
- 사진 + 짧은 스토리 (3~4문장): 왜 이 사람 말을 들어야 하는가
- 숫자로 된 증거 2~3개: 코칭 인원, 팔로워 성장 사례, 활동 연차 등
- 톤: 자랑이 아니라 "나도 당신과 같은 지점에서 시작했다" 서사

### ⑤ 사회적 증거 (Social Proof)
- 수강생/코칭 후기 2~3개 (실명 이니셜 + 직업, 짧은 인용문)
- 후기가 아직 없다면 이 섹션은 v1에서 생략하고 자리만 설계

### ⑥ FAQ (이탈 방어, 3~4개)
- "정말 무료인가요?" / "받은 이메일로 뭐가 오나요?" / "초보자도 할 수 있나요?" / "개인정보는 어떻게 관리되나요?"

### ⑦ 파이널 CTA (폼 2차 반복)
- 헤드라인: "7일 뒤의 당신은 오늘의 결정에서 시작됩니다"
- 이메일 폼 반복 (Hero와 동일 폼)
- 긴박감 요소(선택): "지금까지 N명이 받아갔습니다"

### ⑧ 푸터
- 상호/이메일 문의처, **개인정보처리방침 링크(모달)**, 저작권 표기
- SNS 링크는 아이콘 최소한으로 (이탈 유도 최소화)

### 제출 완료 상태 (Thank You)
- 별도 페이지 대신 폼 영역이 성공 상태로 전환 (SPA)
- "신청 완료! 아래 버튼으로 바로 받아가세요" + 다운로드 버튼
- (선택) 다음 단계 제안: "받으셨다면 인스타에서 만나요" 팔로우 버튼

## 3. 이메일 폼 & DB 수집 설계

### 폼 필드
| 필드 | 필수 | 검증 |
|---|---|---|
| 이름 | 선택 (필드 수가 적을수록 전환율 ↑) | — |
| 이메일 | 필수 | 형식 검증 + 중복 제출 방지 |
| 개인정보 수집·이용 동의 | 필수 체크박스 | 미체크 시 제출 불가 |

- 개인정보 동의 문구: "이메일은 자료 발송 및 뉴스레터 발행에만 사용됩니다" + 처리방침 모달 링크
- 스팸 방지: honeypot 필드 (봇 차단, 사용자에겐 안 보임)

### DB 수집 방식 — 선택지 비교

| 옵션 | 비용 | 난이도 | 특징 | 추천도 |
|---|---|---|---|---|
| **A. Google Sheets (Apps Script Webhook)** | 무료 | 낮음 | 시트에 바로 쌓임, 관리 익숙함. 자동 이메일 발송은 별도 | ★★★ (v1 추천) |
| B. Formspree / Getform | 무료~유료 | 최저 | 5분 연동, 월 제출 수 제한 | ★★ |
| C. Stibee / Mailchimp API 직결 | 무료 티어 | 중 | 수집 즉시 자동 웰컴메일 + 자료 발송 가능 | ★★★ (뉴스레터 운영 시 최종형) |
| D. Supabase | 무료 티어 | 중 | 자체 DB, 확장성 최고. 관리 UI는 직접 | ★ (지금 단계엔 과함) |

**추천 로드맵**: v1은 **A(구글시트)** 로 빠르게 시작 → 뉴스레터 정착 시 **C(스티비)** 로 이전.
프론트는 `submitLead(email)` 함수 하나로 추상화해서 백엔드 교체가 한 줄 수정으로 끝나게 설계.

### 데이터 스키마 (시트 컬럼)
`제출일시 | 이름 | 이메일 | 유입경로(utm_source) | 페이지경로 | 동의여부`
- URL의 UTM 파라미터를 자동 캡처해서 함께 저장 → 어느 채널이 리드를 만드는지 추적

## 4. 디자인 가이드

### 4.1 무드 & 키워드
**"따뜻한 전문가"** — 신뢰(코치) + 친근함(퍼스널). 차갑고 기업적인 느낌 배제.
키워드: warm, editorial, confident, minimal

### 4.2 컬러 팔레트
| 역할 | 컬러 | HEX | 용도 |
|---|---|---|---|
| Background | 웜 아이보리 | `#FAF7F2` | 페이지 기본 배경 |
| Surface | 화이트 | `#FFFFFF` | 카드, 폼 배경 |
| Text Primary | 딥 브라운블랙 | `#2B2420` | 헤드라인, 본문 |
| Text Muted | 웜 그레이 | `#8A7F75` | 보조 텍스트 |
| **Accent (CTA)** | 테라코타 | `#D96C47` | 버튼, 강조 텍스트, 아이콘 |
| Accent Hover | 딥 테라코타 | `#C05A38` | 버튼 hover |
| Success | 세이지 그린 | `#6B8F71` | 제출 완료 상태 |

- CTA는 페이지에서 **테라코타 단 하나의 컬러만** 사용 — 시선이 버튼으로만 모이게
- 다크모드 없음 (전환용 랜딩은 단일 테마가 유리)

### 4.3 타이포그래피
| 용도 | 폰트 | 스타일 |
|---|---|---|
| 헤드라인 | **Nanum Myeongjo** 또는 Noto Serif KR | 세리프 — 에디토리얼/전문가 무드 |
| 본문·UI | **Pretendard** | 산세리프 — 가독성 |

- 스케일 (모바일 기준): H1 32~40px / H2 24~28px / 본문 16~17px / 캡션 13~14px
- 행간: 헤드라인 1.3, 본문 1.7 (한글 최적)
- 헤드라인 내 핵심 구절만 테라코타 컬러 또는 형광펜 스타일 하이라이트

### 4.4 레이아웃 & 스페이싱
- 콘텐츠 최대 폭: 텍스트 640px, 섹션 컨테이너 1040px
- 섹션 수직 패딩: 모바일 80px / 데스크톱 120px
- 폼: 데스크톱은 이메일 입력 + 버튼 인라인 한 줄, 모바일은 세로 스택
- 버튼: 높이 56px(모바일 터치 최적), radius 12px, 풀블리드 아님
- 카드 radius 16px, 그림자는 은은하게 (`0 4px 24px rgba(43,36,32,0.06)`)

### 4.5 비주얼 요소
- 미끼자료 PDF 3D 목업 1개 (Hero) — 실물감이 신청 전환의 핵심
- 아이콘: 라인 스타일 (lucide-react), 컬러는 테라코타/뮤티드만
- 사진: 코치 프로필 1장 (자연광, 웜톤 보정)
- 배경 장식: 아주 옅은 그레인 텍스처 또는 부드러운 라디얼 그라디언트 (과한 장식 금지)

### 4.6 모션 (기존 스택 GSAP/Framer Motion 활용, 절제해서)
- 섹션 진입 시 fade-up (0.5s, 한 번만)
- CTA 버튼: hover 시 살짝 상승 + 그림자 확대
- 제출 성공: 체크 아이콘 스프링 애니메이션 + 폼 → 완료 상태 크로스페이드
- 패럴랙스/스크롤 하이재킹 금지 — 전환 페이지에서 모션은 조미료

## 5. 기술 구현 계획 (기존 스택 그대로)

- **스택**: React 18 + Vite + TypeScript + Tailwind (현재 리포 구성 유지)
- **라우팅**: 기존 포트폴리오와 분리 — `/coach` 라우트 또는 별도 진입점 (구현 시 결정)
- **컴포넌트 구조**:
  ```
  src/pages/CoachLanding.tsx
  src/components/coach/
    Hero.tsx  PainPoints.tsx  LeadMagnetPreview.tsx
    AboutCoach.tsx  Testimonials.tsx  Faq.tsx
    LeadForm.tsx        ← 폼 로직 단일 소스 (Hero/Final 공용)
    PrivacyModal.tsx  Footer.tsx
  src/lib/submitLead.ts  ← 백엔드 어댑터 (구글시트 → 스티비 교체 지점)
  ```
- **SEO/공유**: OG 태그(제목·설명·목업 이미지), 파비콘, `lang="ko"`
- **측정**: GA4 또는 Meta Pixel 스니펫 자리 마련, 제출 성공 시 전환 이벤트 발생

## 6. 오픈 확인 사항 (구현 전 결정 필요)

1. **미끼자료 실물**: 제목·형태(PDF?) 확정된 것이 있는지, 아니면 위 예시 컨셉으로 카피를 잡을지
2. **코치 정보**: 이름/사진/경력 숫자 — 없으면 플레이스홀더로 구현 후 교체
3. **DB 방식**: 구글시트(v1 추천)로 시작할지, 스티비 계정이 이미 있는지
4. **라우팅**: 기존 포트폴리오(`/`)와 별개로 `/coach` 경로에 둘지, 이 브랜치에서는 이 페이지를 메인으로 할지
5. **도메인/배포**: 배포처(Vercel/Netlify 등) 정해진 곳이 있는지
